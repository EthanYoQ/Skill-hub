# Real receipt replay

Cloud qualification is too slow to serve as the verifier's ordinary feedback loop. Preserve real platform-produced receipt bytes and replay them locally through the final consumer before dispatch.

## Pipeline

```text
raw platform bytes
  -> strict decoding for the declared encoding
  -> representation normalization
  -> canonical domain facts
  -> semantic validation
  -> raw-byte identity binding
```

Normalization may reconcile only a documented representation difference. It cannot erase provenance or make unsafe evidence acceptable.

## Known representation cases

- UTF-8 BOM versus no BOM in JSON generated by Windows PowerShell.
- CRLF/CR versus LF in eligible text lockfiles.
- `.NET` seven-digit fractional timestamps versus JavaScript millisecond timestamps when both parse to the same allowed instant.
- PE `ProductVersion` four-part representation such as `0.8.1.0` versus semantic application version `0.8.1`, using an explicit comparison rule.
- Windows 8.3 versus long paths only after both resolve to the same trusted file and parent chain.
- macOS ad-hoc signing versus Developer ID signing as different policy states, never as interchangeable signatures.
- A localhost probe that resolves to IPv6 `::1` versus an application listener bound only to IPv4 `127.0.0.1`; validate the declared endpoint family instead of treating the hostname as proof of reachability.
- PowerShell modules required for Authenticode or platform inspection must be imported explicitly and their actual command source/version recorded; autoload success is not a portable assumption.

## Fixture integrity

- Preserve the original receipt bytes, raw SHA-256, producer platform, workflow/run/attempt, tool version, and expected semantic facts.
- Permit at most one UTF-8 BOM at byte zero for JSON parsing. Reject duplicate, partial, misplaced, or UTF-16 BOMs, invalid UTF-8, and malformed JSON while preserving the original bytes for hashing.
- Use real successful platform output as positive fixtures. Do not generate positives with the verifier helper being tested.
- Construct negative fixtures independently: altered artifact hash, wrong source SHA/version, duplicate BOM, invalid encoding/date, unsafe path, missing observation, extra asset, or signing disclosure mismatch.
- Replay the complete known set after any schema, decoder, normalizer, verifier, or promotion change.
- When a new cloud representation appears, first archive the raw bytes and add a red regression. Fix locally and replay all fixtures before another formal run.

The bundled replay script validates the common receipt envelope. Project verifiers remain responsible for domain-specific fields and cross-file relationships.
