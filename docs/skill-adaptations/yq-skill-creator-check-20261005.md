# Skill Creator 发布前校验

本次校验只针对三个 DeepSeek Harness 派生 Skill 的最小通用化改写。
用户的原文与能力保留要求优先于一般的精简或润色建议。

## 校验结果

| 检查对象 | 结果 |
| --- | --- |
| 三个 Skill 的名称与 frontmatter | 平台 quick_validate.py 全部通过。 |
| 原文与两阶段差异 | 八个既有文件可由固定上游与登记差异逐字节重建。 |
| 新 testing-principles 参考 | 可由固定上游三个相邻章节和登记差异逐字节重建。 |
| 测试政策 | 目标仓库拥有层级、命令、覆盖率和外部 API 要求，不继承 DSH 固定门槛。 |
| 异步状态 | 整体 idle 不证明单条消息完成；队列取消、区间归属及无可等待事件的分支保留。 |
| 字体规则 | 遵循目标主题既有层级；不再强制 DSH 500 上限。 |
| 窗口适配 | 使用应用实际平台标识；共享避让量不能为单页改动；局部测试和总偏移核对保留。 |
| 测试能力 | 真实入口、发布产物、外部边界模拟、消费者验证、负向对照、资源清理保留。 |
| 权限与停止边界 | 诊断和审计请求保持只读，不授权修复、CI 重跑或其他外部操作。 |

独立 Skill Creator 复核未发现源文件的实质语义缺陷。
案例应用是离线检验，没有执行真实 CI、GUI 或模型流程。
不宣称等同于上游完整验证结论。

## 全局安装的路径映射

分组仓库中，yq-ui-checks 使用以下有效目标：

    ../../08-writing-marketing/yq-technical-writing/SKILL.md

在 Codex 的扁平 ~/.codex/skills 目录中，只把该目标调整为：

    ../yq-technical-writing/SKILL.md

安装时必须验证目标存在，且除这一链接目标外的全部字节与发布版本一致。
其余 Skill 与参考文件按原字节安装。MIT 版权署名继续保留。
这是一项安装布局映射，不是改写通用规则。

## 发布范围

只发布这三个 Skill、对应报告、来源记录和必要的仓库索引与数量更新。
通过最新远程 mine 的独立副本发布，不连带上传本地其他未推送提交。
公开副本不包含 projects/ 下的私人项目文件。
索引根据公开副本的实际文件重建；本地含项目技能的索引数量可能不同。

## 原文空行与差异检查

新 testing-principles 参考保留了上游三节片段的末尾空行。
默认 git diff --cached --check 对这一行报告 new blank line at EOF。
这不是新增规则或能力缺陷；按用户不调整原文格式的要求保留。
发布时只将这一已核实的空行排除出 whitespace 检查，其他空白错误仍检查。
没有修改仓库永久配置，没有绕过 Git hooks。
