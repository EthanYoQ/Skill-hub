# 任务卡模板

## 1. 任务卡格式

追问结束后，照这个格式写。没有内容的栏目整栏删掉，不要写「无」。填好的卡不超过 15 行；超了就把边界句合并、把假设删到最要紧的 3 条。

```
## 任务卡

**任务**：【一个动词加一个对象】，用于【用途】
**我是谁 / 读者**：【岗位】；结果给【谁】看
**背景**：【对象、场景、时间点】
**资料与边界**：只依据【资料清单】；【其他边界句，从 gap-checklist.md 取】
**格式**：【形式、长度、结构】
**核对**：每条结论标出处；推断标【推断】；最后列出不确定的地方
**步骤**（多步任务才写）：1. 【做什么】→ 产出【什么】，查【什么】　2. ……
**留给你决定的**（结论类决定才写）：【决定事项】：可选【A / B】；判断时最该看【因素 1、因素 2】
**我做的假设**（没问、按默认处理的，可以改）：【假设 1】；【假设 2】
```

写法要求：

- 「任务」一栏只写一件事。用户要做几件事时，写最先做的那件，其余放进「步骤」。
- 「格式」一栏写到这个任务的具体结构：表格写出列名，幻灯片写出页的组成和页数，问答写出几问几轮。只写「表格」「幻灯片」不够。
- 用户回答里说的具体要求（列名、页数、时长、人群），原样写进对应栏目，不要概括掉。
- 边界句用 `gap-checklist.md` 里现成的句子，不自己发明说法。
- 「我做的假设」是用户确认时最容易漏看的地方，放在最后，单独列出。
- 发给用户之前，按 `method.md` 第 1 节的「任务卡自检清单」对一遍。

## 2. 示例

### 示例一：药企，分析数据

用户原话：「帮我分析一下这些患者留言。」（附件：某平台留言 3000 条）

经过一轮追问（用途、读者、数据范围）后：

```
## 任务卡

**任务**：归纳患者最常提到的困扰，用于安排下季度的患者教育主题
**我是谁 / 读者**：【产品】品牌经理；结果给市场部内部看
**背景**：本季度公开平台上【疾病】相关的患者留言，共 3000 条，已去掉昵称和头像
**资料与边界**：只依据留言原文，不推断个人身份；在任何分析之前，疑似不良事件单独列出，不判断药和不适有没有关系；占比写成「留言中」，不写成「患者中」
**格式**：困扰排序表，每类写占比（分母为全部留言）和 2 条原文
**核对**：先报告读取了多少条；占比用代码计算；推断标【推断】
**步骤**：1. 数据检查 → 检查结果和口径卡草稿，你确认后再往下　2. 单列疑似不良事件 → 交药物警戒　3. 按话题归类（可多选），抽 20 条你自己归一遍看一致率　4. 计算占比并排序
**我做的假设**：一个话题少于 30 条的，只作方向参考
```

### 示例二：非医药，产出材料

用户原话：「帮我写个季度复盘，下周给老板看。」（附件：三个月的周报）

经过一轮追问（用途、老板最关心什么、篇幅）后：

```
## 任务卡

**任务**：起草第三季度工作复盘，用于下周一和部门负责人的季度会
**我是谁 / 读者**：运营组长；读者是部门负责人，只看结论和数字
**资料与边界**：只依据 7–9 月的 13 份周报；周报里没有的写「资料未提及」；下季度目标值由我定，标【待定】
**格式**：一页纸。先写三条结论，每条下面放数字和对应周报的日期；最后写两项没完成的事和原因
**核对**：每个数字标来自哪份周报；推断标【推断】；最后列出不确定的地方
**留给你决定的**：下季度优先做哪件事：可选【拉新 / 留存】；判断时最该看【预算、人手】
**我做的假设**：不写形容词，只写数字；不评价同事个人表现
```

## 3. 只要提示词时：改写成六要素提示词

用户说「给我一条提示词，我拿去别的工具用」时，把任务卡改写成下面的样子（提示词 1-1 的格式）：

```
我是【岗位】，负责【领域或产品】。
背景：【对象、场景、时间点】
任务：请帮我【整理／比较／起草／检查】【对象】，用于【用途】。
边界：只依据我提供的资料：【粘贴或上传】。【其他边界句】资料里没有的，写「资料未提及」，不要补充。
格式：【表格／一页纸／要点】，不超过【字数或页数】，读者是【谁】。
核对：每条结论标出处（资料名称和页码或条目）；推断标【推断】；最后列出你不确定的地方。
```

多步任务在末尾加上这几句（提示词 3-2）：「先不要执行。请把这项任务拆成 3–6 步」，每一步写清做什么、输入输出、要查什么、要不要用代码；「等我确认步骤后，再从第一步开始，每次只做一步。」

## 4. 存成模板（结果好用时）

模板卡结构（提示词 5-3）：

| 项目 | 填写 |
|---|---|
| 名称 | |
| 适用岗位和场景 | |
| 要准备的资料 | |
| 提示词 | 把对话里陆续补充的要求合并进去；具体的产品、医院、数字换成【】 |
| 拿到结果先查 | 这次发现并纠正过的错误，写成要查的地方 |
| 已知问题 | 这条提示词在什么情况下效果不好 |
| 版本和日期 | |

只把核对过、确实好用的对话存成模板；合并时只整理，不添加对话里没有的要求。
