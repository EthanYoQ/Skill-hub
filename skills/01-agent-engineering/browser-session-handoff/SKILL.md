# Chrome 登录状态交接

用于把用户已授权的 Chrome 登录状态交给其指定设备或 Agent。先确认源 Chrome 配置、目标配置和允许操作的站点。已经接入的官方 API 或 OAuth 继续使用原接入方式。

## 导出

1. 在源配置打开已授权站点的 HTTPS 后台，确认账号及登录状态。优先使用当前浏览器工具已获准的按标签页读取能力。若提供 CDP，按 [操作手册](references/handoff.md) 调用带显式 URL 的 `Network.getCookies`。仅在本地受控运行时接收返回值。
2. 逐站点筛选第一方、未分区、未过期的 Cookie。保留域、路径、HostOnly、Secure、HttpOnly、SameSite 和会话期限。若工具未提供合规读取能力，可使用随附扩展，在 Chrome 中由用户确认该站点权限。权限被拒绝时停止该站点。
3. 在内存中规范化和加密。每站点生成一份经认证的密文，用独立随机 salt 和 IV，并把格式及站点绑定到认证数据。将已生成文件回读解密，在内存中与原记录比对。
4. 将各站点密文、匹配的导入器和通用说明合为一个私下交接的 ZIP。检查清单并记录 SHA-256。口令单独存入用户指定的密码管理器或系统凭据存储，通过独立途径交接。

## 导入与验收

在目标 Agent 实际使用的专用 Chrome 配置中导入。检查归档哈希、站点和格式。保留配置中原有的 Cookie。打开相应平台后台，用只读方式核对账号和评论入口。平台要求重新验证时，由用户在目标设备完成。

报告逐站点的结果，区分「已导出并回读」「已写入目标配置」「目标后台已确认登录」。导入计数只代表浏览器写入结果。Cookie 值、口令、真实密文和私人路径仅保存在受控环境，公开说明使用占位符。

[操作手册](references/handoff.md)包含字段映射、单 ZIP 清单、目标端操作和故障分流。随附本地扩展支持抖音、小红书、知乎和 TikTok。
