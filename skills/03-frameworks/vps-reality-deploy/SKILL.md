# 部署可恢复的 REALITY 与 TUIC 代理

为用户控制的 Linux VPS 部署 VLESS + XHTTP + REALITY，按需求增加 TUIC v5 UDP 备用，交付 Clash Verge YAML、Shadowrocket 二维码和私密恢复文档。这里的 VPN 是代理加客户端 TUN，不是 WireGuard 或站点间组网。

先区分需求：两个同协议账户、TCP/UDP 双协议，或独立线路。用户说“两个节点”时，先从上下文判断；仍不明确才询问，不能默认用两个 UUID 代表双协议。已明确要主备协议时，采用 VLESS XHTTP REALITY（TCP）加 TUIC v5（UDP），并实测目标网络能否使用 UDP。同一 VPS 的两个协议仍共享 IP 和主机故障域；线路冗余需要不同服务器或网络。

## 确认现场

读取用户指定的服务器信息或已授权的相关邮件。记录 OS、架构、SSH 端口、现有服务、TCP/UDP 端口、防火墙、恢复控制台、客户端内核版本和时钟状态。已有配置先保存精确备份和 SHA256。缺少登录信息时仅询问缺失项，先做不依赖该信息的工作。

沿用当前任务的授权范围。文件交付不等于允许导入客户端、修改系统代理或启用 TUN。

默认使用官方 Xray 直接部署。用户明确要求 3X-UI 时保留其选择，并核对实际核心配置。不得把 XHTTP 换成 TCP Vision 或 Hysteria 后声称与指定方法一致。

## 执行流程

1. 读 [部署与恢复](references/deployment.md)，检查官方文档和版本兼容性。新部署生成新凭据；维护时保留未要求轮换的凭据。新增 TUIC 使用独立服务，保留已工作的 VLESS；旧兼容账户等用户确认导入成功后再按授权清理。
2. 新增 TUIC、证书或排查间歇断流时，读 [时钟与 TUIC](references/clock-tuic.md)。先核对系统实际偏差，不能只看 NTP 服务已启动。
3. 需要部署或更换 REALITY 目标时，读 [伪装目标筛选](references/target-selection.md)。从 VPS 实测候选，没有明确改善就保留现状。
4. 建立仅本地保存的私密参数记录，包含服务器、SSH、版本和按协议区分的凭据。读 [客户端与交付](references/delivery.md)，从该记录生成 YAML、各协议 URI、本地二维码、备份和 MD。密钥不进入仓库、聊天正文或外部二维码服务。
5. 读 [验收](references/verification.md)，逐协议验证真实代理、失败认证和交付一致性。长流、多客户端、证书续期分别记录；失败则按明确回滚命令恢复已验证状态。

## 完成条件

报告文件位置、实际协议和端口、各节点测试结果、回滚位置及未测范围。区分配置检查、隔离内核、三进程并发和真实设备测试；短时通过不能代替 15 分钟长流或证书续期验证。

复用经过测试的配置基线，不把历史域名或版本当作永久最佳选择。伪装、加密和 DNS 路由可以逐项验证；长期防封、全国运营商可用性和账户风控不能由一次握手或测速证明。
