# 部署可恢复的 XHTTP REALITY 代理

为用户控制的 Linux VPS 部署 VLESS + XHTTP + REALITY，交付 Clash Verge YAML、Shadowrocket 二维码和私密恢复文档。这里的 VPN 是代理加客户端 TUN，不是 WireGuard 或站点间组网。

默认交付同一 VPS 上两个独立 UUID 的节点。它们共享 IP、入口和故障域，不是两条独立线路。需要线路冗余时使用不同服务器或网络。

## 确认现场

读取用户指定的服务器信息或已授权的相关邮件。记录 OS、架构、SSH 端口、现有服务、端口占用、防火墙管理器、恢复控制台和客户端内核版本。已有配置先保存精确备份和 SHA256。缺少登录信息时仅询问缺失项，先做不依赖该信息的工作。

沿用当前任务的授权范围。文件交付不等于允许导入客户端、修改系统代理或启用 TUN。

默认使用官方 Xray 直接部署。用户明确要求 3X-UI 时保留其选择，并核对实际核心配置。不得把 XHTTP 换成 TCP Vision 或 Hysteria 后声称与指定方法一致。

## 执行流程

1. 读 [部署与恢复](references/deployment.md)，检查当前官方文档和版本兼容性。备份后再改服务器。新部署生成新凭据；维护时保留未要求轮换的凭据。
2. 读 [伪装目标筛选](references/target-selection.md)，从 VPS 实测候选，包括有公开来源依据的同 ASN 网站。实际代理通过后才能确定目标，没有明确改善就保留现状。
3. 建立一份仅本地保存的私密参数记录，包含服务器、SSH、版本、目标、路径、REALITY 密钥对，以及两个 UUID 和 short ID。所有服务端和客户端输出从该记录生成。
4. 读 [客户端与交付](references/delivery.md)，生成 YAML、两个 VLESS URI、两张本地二维码、备份和 MD。私密交付与公开文件分开，不向仓库、聊天正文或外部二维码服务传入密钥。
5. 读 [验收](references/verification.md)，逐节点验证真实代理、失败认证、伪装行为和交付一致性。失败则恢复已验证状态，并说明未完成项。

## 完成条件

报告文件位置、实际协议和目标、两节点测试结果、回滚位置及未测范围。区分配置检查、隔离内核测试和真实客户端测试。

复用经过测试的配置基线，不把历史域名或版本当作永久最佳选择。伪装、加密和 DNS 路由可以逐项验证；长期防封、全国运营商可用性和账户风控不能由一次握手或测速证明。
